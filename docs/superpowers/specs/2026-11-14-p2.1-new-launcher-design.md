# P2.1 New launcher: design

Package P2.1 in [packages](../../packages.md#day-lane). Decisions: [design answers, New launcher](../../reference/design-answers-2026-11-08.md#new-launcher-user-2026-11-13) (2026-11-13, open points settled 2026-11-14). Mockups: `minimal-*` in [launcher mockups](../../images/launcher-mockups/). The movement design rider of P2.1 is a separate document and session; this design covers the launcher only.

## Intent

The P2 playtest card rated the menu 2 of 5 (STATUS P2 row). Today's launcher is one centred column holding offline, online, join, wait, relay, audio, playtest, credits and legal at once. P2.1 replaces it with a sidebar launcher whose Play page starts a bot match in one click with the last picks, and whose Friend and Join paths make inviting a friend obvious. The layout is the one the later fancy set restyles, so structure decided now carries forward.

## Goals

- Sidebar: Play, Join, a divider, Settings, Credits; version string at the bottom (`application/config/version`). The selected item has a green fill.
- **Play** ([bot](../../images/launcher-mockups/minimal-play-bot.webp), [friend](../../images/launcher-mockups/minimal-play-friend.webp)): You (faction dropdown), Opponent toggle Bot | Friend, Map dropdown with a "N start positions · N supply sources" line under it. Bot: a Bot faction dropdown; footer summary "Map · You vs Bot-faction bot" and **Start match**. Friend: a dashed "Open slot, your friend picks their own faction" row, Advanced settings (relay URL, prerelease builds only, labelled TEST BUILDS ONLY); footer hint "You get a link to send to your friend." and **Create match**.
- **Waiting** ([mockup](../../images/launcher-mockups/minimal-waiting.webp)), shown after Create match succeeds: invite link with Copy link (Copy code outside the web build, as today), "Or tell them the code: XXXXXX", Players (1 You + faction + READY badge, 2 Open "waiting for your friend…" dashed), the map panel, footer match code and **Cancel match**. Sidebar locked; Cancel match is the only way out and returns to Play with the picks kept.
- **Join** ([mockup](../../images/launcher-mockups/minimal-join.webp), [error](../../images/launcher-mockups/minimal-join-error.webp)): Match code field with "Opened a join link? The code is already filled in.", You (faction), Map column "The host chooses the map.", **Join match**. Errors show in a footer line left of the button. Advanced settings as on Friend.
- **Settings** ([mockup](../../images/launcher-mockups/minimal-settings.webp)): Audio (today's `VolumeSliders`), a Fullscreen switch (rider), Playtest (today's switch, its one-line explanation, and "This build: <card title>" opening today's focus card panel while the switch is on).
- **Credits** ([mockup](../../images/launcher-mockups/minimal-credits.webp)): today's credits text (`Credits.text(...)`) in a panel, plus today's legal line.
- **Startup:** opens on Play with Bot selected and the remembered picks. With a valid `?code=` it opens on Join with the code filled (today's `code_applied` guard stays: a stale link does not refill after "back to menu").
- **Remembered picks:** your faction, the bot's faction and the map, in section `[launcher]` of `user://settings.cfg` (beside `[audio]`). Saved when a match starts (see agent calls for the joiner case). A stored value that is no longer a valid id falls back to its default per field, silently (faction: `DEFAULT_FACTION`; bot faction: today's opponent default; map: first in `MatchSettings.PLAY_MAPS`). Join uses the same remembered own faction.
- **Fullscreen** (rider, user 2026-11-13): desktop only, borderless fullscreen, remembered in `[launcher]`. Not in the web build (user, 2026-11-14): there the browser's own fullscreen does the job.
- **No black bars in the launcher** (user, 2026-11-14): the user's concern is the black bars in a maximized, not 16:9, browser window; they come from stretch aspect `keep` (`game/project.godot` sets `canvas_items` with no aspect). The launcher is laid out on edge anchors and sets the root's `content_scale_aspect` to `expand` while it is shown, restoring `keep` when it leaves the tree (any match start or test teardown). The match keeps `keep` and its bars until P2.3a anchors the HUD.
- **Playtest card question:** P2.1's focus card asks whether the locked sidebar while waiting was annoying (user, 2026-11-14).

## Non-goals

- The fancy set (flat dark look, emblems, map thumbnail, bot level and play style).
- Project-wide stretch aspect `expand`, HUD anchoring and the in-match non-16:9 layout test (P2.3a).
- Any relay, protocol or simulation change. Codes stay 6 characters from `relay/room.go`.
- Controls for features that do not exist: bot level, starting money, game speed, a ready step.

## Anti-goals

- Losing today's behaviour: headless netclient flags, paste shim on web, M mute key in the launcher and text fields, menu music, playtest focus cards, relay URL from `?relay=` in prerelease builds, the protocol error and refusal paths.
- A stray click that drops a pending invite (hence the locked sidebar).

## Constraints

- Godot 4.7.2, `gl_compatibility`, typed GDScript, lint and warnings gates.
- Headless layout tests at 1280x720, 1920x1080 and one wide size of about 2.25:1 (the user's maximized Firefox page area, 2576x1145 physical pixels on 2026-11-14: menu bar and Dock visible, which is what "full screen" means to the user): nothing clipped or overlapping, no unused band at an edge, every page; a test that a match start restores `keep`.
- Tests reach launcher nodes by path in `test_join_link.gd`, `test_online_scene.gd`, `test_audio_settings.gd`, `test_pause_menu.gd`, `test_playtest_overlay.gd`; those move with the new paths, their checks keep their meaning.
- `game/scripts/presentation/` code is presentation: no simulation or trace change; replay and trace pins unchanged.

## Approaches

- **A. One scene, pages as siblings (picked, user 2026-11-14).** `launcher.tscn` becomes sidebar + content area with Play, Join, Settings, Credits and Waiting containers, one visible at a time. `launcher.gd` keeps connection, link and start logic; remembered picks in a small `launcher_settings.gd` modelled on `audio_settings.gd`. One `Theme` resource for the grey look and green selected fill. Keeps today's structure, so tests change paths but not shape.
- B. A scene per page under a shell. Rejected: the relay connection must outlive page changes (Waiting), so its state would move into a shared node; more parts for five small pages.
- C. UI built in code. Rejected: loses the scene file the layout tests and the later fancy restyle lean on.

## Decided details (user)

Sidebar locked while waiting; `?code=` opens Join filled, no auto-join; READY badge kept as decoration, so the layout slot exists when the M9 lobby adds a real ready step (agent note: the badge itself builds no part of that step; the M9 lobby must still add it); Bot/Friend selected side in the sidebar's green, other side dark; per-field silent fallback; 6-character codes; remember faction, bot faction, map; always open on Bot; a lost connection or relay error while Waiting returns to Play with the reason in Play's footer line and the picks kept, like Cancel match (2026-11-14). Structure, two sets one layout, dropdowns, no Back button, no mode-card screen, Fullscreen setting, layout test sizes (2026-11-13).

## Agent calls (correctable)

- The sidebar locks from the click on Create match or Join match until the match starts or the attempt fails, not only on Waiting: one busy state, like today's `_set_busy`.
- "You" is one value shared by Play and Join: changing it on either page changes the other. A joiner's match saves only your faction, never the host's map; bot matches and hosted matches save faction, bot faction and map.
- Legal line moves to the Credits page.
- Advanced settings appear on both Friend and Join (joining a test relay needs it too; today one field serves both).
- Status texts keep today's strings ("Connecting…", "Cannot connect to relay", protocol errors) in the footer line of the page that started the connection.
- Fullscreen on web is not restored at load (browsers require a click to enter fullscreen); the switch reflects the current state.

## Left to the builder

Node names and the paths tests use; exact colours and font sizes from the mockups; how the version string is read; whether the opponent toggle is two `Button`s in a `ButtonGroup`.
